# Codex model selection

The bootcamp may suggest a model or reasoning-effort change at a module boundary. It cannot make
that change itself. In the Codex desktop app or IDE, tell the bootcamper to use the visible model
and reasoning controls. In the Codex CLI, describe the intent without inventing a command.

Use the user's current configured model by default. For long planning, data-mapping, debugging, or
graduation work, recommend a capable Codex model with medium or high reasoning. For short setup and
status steps, the current model is normally sufficient. Do not embed a time-sensitive model name,
price, or context-window claim in this versioned plugin.
